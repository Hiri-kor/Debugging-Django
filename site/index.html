HTTP Request Method 4가지

10점
부족한 답안 예시
-GET: 조회 요청, POST: 생성 요청, PUT: 수정 요청, DELETE: 삭제 요청
보완할 점
메서드와 CRUD 대응은 맞습니다. 각 메서드가 무엇을 대상으로 하는지(목록인지 단건인지), 요청 본문이 필요한지, 성공 시 상태 코드가 무엇인지까지 쓰면 “목적”을 설명했다고 볼 수 있습니다. 첫 줄의 “-GET” 은 “- GET” 으로 띄어 써야 목록으로 보입니다.
MethodCRUD목적이 프로젝트 예시성공 응답
GETRead서버 데이터를 바꾸지 않고 리소스를 조회GET /api/v1/books/ 목록
GET /api/v1/books/1/ 상세		200 OK

모범 답안 펼치기
- GET : 리소스를 조회(Read)할 때 사용한다. 서버의 데이터를 변경하지 않으며, 목록 조회(GET /books/)와 단건 상세 조회(GET /books/1/)에 쓰인다. 성공 시 200 OK. - POST : 새 리소스를 생성(Create)할 때 사용한다. 요청 본문(body)에 담긴 데이터를 serializer로 검증한 뒤 저장하며, 성공 시 201 Created로 생성된 데이터를 응답한다. - PUT : 기존 리소스를 수정(Update)할 때 사용한다. URL로 대상을 지정하고 본문의 데이터로 수정하며, 원칙적으로 전체 필드를 교체한다. DRF에서는 partial=True 옵션으로 일부 필드만 수정할 수 있다. 성공 시 200 OK. - DELETE : 지정한 리소스를 삭제(Delete)할 때 사용한다. 성공 시 응답 본문 없이 204 No Content를 반환한다.

Serializer의 many=True 옵션

10점
부족한 답안 예시
- 단일 대상이 아닌 다량의 것을 받을 때 사용한다.
보완할 점
“다량의 것”이 무엇인지 구체적으로 써야 합니다. 직렬화 대상이 QuerySet이나 리스트처럼 여러 객체라는 점, 내부적으로 ListSerializer가 각 객체를 같은 규칙으로 변환해 리스트로 돌려준다는 점, 쓰지 않으면 오류가 난다는 점을 예시와 함께 적어 주세요.
 # 1) 목록 조회: QuerySet(여러 객체) → JSON 배열 books = get_list_or_404(Book) serializer = BookListSerializer(books, many=True)  # 2) 역참조 중첩: 도서 1개에 달린 댓글 여러 개 comment_set = CommentDetailSerializer(many=True, read_only=True)
모범 답안 펼치기
- many=True는 직렬화(또는 역직렬화)할 대상이 단일 객체가 아니라 QuerySet이나 리스트처럼 여러 개의 객체일 때 사용한다. - 이 옵션을 주면 DRF가 내부적으로 ListSerializer를 만들어 각 객체를 같은 serializer 규칙으로 하나씩 변환하고, 결과를 JSON 배열(리스트)로 반환한다. - 예) 도서 목록 조회: BookListSerializer(books, many=True) - 예) 1:N 역참조 중첩 필드: 도서 상세에 댓글 목록을 넣을 때 comment_set = CommentSerializer(many=True, read_only=True) - 여러 객체를 넘기면서 many=True를 빠뜨리면, serializer가 QuerySet/리스트 자체를 하나의 객체로 보고 필드를 찾다가 AttributeError가 발생한다.
